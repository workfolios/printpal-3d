## Decision-Support Integrity Controls

- AI request payloads contain only normalized deterministic Comparison facts and record identifiers.
- Deterministic facts remain separate from interpretation fields.
- AI and fallback outputs use structured schemas and common response envelopes.
- Both server and client reject prohibited causal, prescriptive, hazardous, fabricated-URL, and unsupported-validation patterns.
- Rules-based fallback remains labeled and usable when AI is unavailable or invalid.
- Interpretation and Next-Test content remain fully editable.
- AI-authored content changes to `AI_ASSISTED_USER_EDITED` after user edits.
- Plans support `DRAFT`, `ACCEPTED`, and `REJECTED` statuses.
- One Next-Test identifier remains linked to one Comparison.
- An accepted plan links to the latest compared Attempt; rejection removes that Attempt link while retaining the auditable plan record.
- Decision-support saving is blocked when the deterministic Comparison is stale.
- Refreshing stale deterministic facts clears prior interpretation and linked Next-Test records.
- No universal technical values, unsafe procedures, or causal diagnoses are generated by the governed fallback.
